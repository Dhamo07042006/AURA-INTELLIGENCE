SECTION 4 — ERROR CODES: EXACT ML FEATURE INJECTION TABLE
====================================================================================================

Analyzed from: backend/services/inference_worker.py → update_features_with_telemetry()

Each error_code directly MODIFIES the ML feature vector before prediction runs.
This is why the error_code is the most important single field for triggering alerts.

ERROR CODE     | ML FEATURES INJECTED                                      | RISK RESULT
---------------+-----------------------------------------------------------+-------------
"OK"           | No modification — uses raw battery/temp/load values only  | LOW
"BAT_WARN"     | Battery_Errors_Last_7_Days → max(current+1, 5)            | MEDIUM
               | Warnings_Last_7_Days → max(current+1, 3)                  |
"BAT_CRITICAL" | Battery_Errors_Last_7_Days → max(current+3, 10)           | CRITICAL !!!
               | Alarms_Last_7_Days → max(current+2, 5)                    |
"TEMP_WARN"    | Alarms_Last_7_Days → max(current+2, 3)                    | MEDIUM–HIGH
"TEMP_CRITICAL"| Alarms_Last_7_Days → max(current+2, 5)                    | HIGH–CRITICAL
"SENSOR_ERR"   | Sensor_Errors_Last_7_Days → max(current+3, 10)            | HIGH !!!
               | Abnormal_Sensors_Last_7_Days → max(current+3, 10)         |
"POWER_WARN"   | Power_Errors_Last_7_Days → max(current+3, 5)              | MEDIUM
"POWER_FLUC"   | Power_Errors_Last_7_Days → max(current+3, 8)              | HIGH !!!
               | Voltage_Fluctuation_Count → max(current+5, 12)            |
"COMM_ERR"     | System_Resets_Last_7_Days → max(current+2, 5)             | MEDIUM
"SYS_RESET"    | System_Resets_Last_7_Days → max(current+2, 5)             | HIGH !!!

COMBINED TRIGGER RULES (most reliable for CRITICAL):
  battery_health < 20  +  "BAT_CRITICAL"   →  failure_prob > 0.90 → CRITICAL
  temperature > 48     +  "TEMP_CRITICAL"  →  failure_prob > 0.85 → HIGH/CRITICAL
  load_percent > 90    +  "SENSOR_ERR"     →  failure_prob > 0.75 → HIGH
  days_since_maint>180 +  "BAT_WARN"       →  failure_prob > 0.72 → HIGH
  All extreme values   +  "BAT_CRITICAL"   →  failure_prob > 0.95 → CRITICAL (cascade)

SECTION 9 — WHAT HAPPENS IN AURA AFTER EACH POST (real-time dashboard updates)
====================================================================================================

This is the complete data flow when LOGx sends a telemetry log:

  LOGx POST ──────────────────────────────────────────────────────────────────────────────────────
    ↓ POST http://AURA:8000/api/v1/ingest/telemetry { payload }
  AURA INGESTION ENDPOINT (/api/v1/ingest/telemetry) ─────────────────────────────────────────────
    ↓ Parses payload fields
    ↓ Maps to ML features:
        battery_health   → Approx_Battery_Health
        temperature      → Average_Temperature_C
        load_percent     → Peak_Load_Percent, Average_Load_Percent
        error_code       → Injects Battery/Sensor/Power/System error counts into feature vector
        voltage          → Voltage_Fluctuation_Count (if low)
  ML INFERENCE ENGINE ─────────────────────────────────────────────────────────────────────────────
    ↓ Logistic Regression: failure_probability (0–1) → risk_level (LOW/MEDIUM/HIGH/CRITICAL)
    ↓ RUL Regressor: predicted_failure_time_days
    ↓ Isolation Forest: anomaly_score (0–100)
    ↓ SHAP Explainer: top 5 contributing features
    ↓ Component Health Calculator: per-component health % (Battery, Power Supply, Sensors...)
    ↓ Root Cause Analyzer: primary cause (Battery Degradation / Power / Sensor / Maintenance / Age)
    ↓ RAG Advisor: recommended maintenance action from knowledge base
  STORAGE ─────────────────────────────────────────────────────────────────────────────────────────
    ↓ device_cache[device_id] = full ML report (in-memory, instant)
    ↓ predictions table: INSERT (SQLite)
    ↓ alerts table: INSERT if risk HIGH or CRITICAL (SQLite)
    ↓ device_logs table: INSERT (SQLite)
  WEBSOCKET BROADCAST ─────────────────────────────────────────────────────────────────────────────
    ↓ Broadcast DEVICE_UPDATE message to ALL connected AURA browser sessions
  AURA DASHBOARD UPDATES (immediate, real-time) ───────────────────────────────────────────────────
    ↓ Monitoring Dashboard: CRITICAL/HIGH/WARNING KPI counters update
    ↓ Fleet Alerts: NEW card appears for HIGH/CRITICAL devices
    ↓ Alert Inbox Panel: slides open with Inspect Twin + Resolve buttons
    ↓ Live Telemetry Table: new row prepended with health/risk/ML recommendation
    ↓ Digital Twin: if device is open in twin view, components update live
    ↓ Risk Heatmap: department risk bar recalculates
  AURA RETURNS JSON RESPONSE ──────────────────────────────────────────────────────────────────────
    ↓ { status, risk_level, overall_health, anomaly_score, device_id }
